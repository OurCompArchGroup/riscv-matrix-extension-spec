== Zmasync: Asynchronous Store Synchronization Extension

=== Overview

The motivation of Zmasync is to allow matrix operations to be pipelined with vector operations, which is required by state-of-the-art kernel libraries such as Flash Attention 3 and DeepGEMM, where matrix multiplication results need post-processing (e.g., precision promotion) that can overlap with the next matrix operation.

The Zmasync extension enables asynchronous execution of matrix operations within a single core. The term "asynchronous" in this context specifically refers to asynchrony between different functional units within a single core (not multi-core or multi-hart asynchrony). This allows matrix operations to overlap with other operations, such as vector or scalar computations, within the same hart.

When the Zmasync extension is implemented together with the AME (Attached Matrix Extension) or its simplified variant, the behavior of matrix load/store/mma/mzero instructions changes: these instructions become non-blocking without any modification to their instruction encoding, and are committed immediately from the pipeline without waiting for completion. However, store results are not guaranteed to be visible to subsequent vector or scalar loads immediately. To ensure the visibility of the store operations, the Zmasync extension introduces a new set of synchronization instructions.

NOTE: The `mcsr` register and its sub-registers (e.g., `mfflags`, `msat`) reflect the results of asynchronous matrix operations only after a corresponding `macquire` instruction is executed. Reading `mcsr` or its sub-registers before `macquire` following an asynchronous matrix operation yields undefined behavior.

==== Sync Register Count CSR, msync

The read-only `msync` CSR (address 0xCC7) reports the number of sync registers. The implementation provides exactly 16 sync registers.

=== Instruction Format

The func4 field distinguishes different synchronization operations. The tok field (inst[24:20]) specifies the sync register index. The ctrl field (inst[25]) is set to 0. For msyncregreset and mrelease, the rs1 field is set to zero. For macquire, the rs1 field specifies the scalar register containing the threshold value.

=== Instructions

==== Reset, Release and Acquire

```
msyncregreset tok0           # Reset sync register tok0 to 0.

mrelease      tok0           # Increment tok0 by 1; waits for store visibility.

macquire      tok0, t0       # Block until tok0 >= t0; ensures store visibility to other units.
```

`msyncregreset` resets the specified sync register to zero, clearing any previously accumulated release count.

`mrelease` increments the sync register by one. It does not commit until all in-flight matrix store instructions from the current thread have been made visible to subsequent vector and scalar loads, ensuring that memory written by those stores is observable before the release count advances.

`macquire` blocks until the sync register value is greater than or equal to the threshold supplied in an integer register. This guarantees that the memory written by matrix store instructions associated with prior `mrelease` operations is visible to other functional units (vector and scalar loads) before any instruction following `macquire` proceeds.

==== Usage Example: DeepGEMM in AME with Zmasync

In DeepGEMM, each GEMM result is promoted from low-precision to full fp32. Asynchronous matrix operations allow the next GEMM to execute while the previous result is being promoted.

```
void async_matmul(c);  // output matrix c

void promotion(c);

void deepgemm_kernel() {
    ...

    tok0 = msyncregreset();

    async_matmul(c[0]);
    mrelease(tok0);  // tok0 becomes 1

    num_iterations = 10;
    for (i = 0; i < num_iterations; i++) {
        if (i < num_iterations - 1) {
            async_matmul(c[i + 1]);  // non-blocking
            mrelease(tok0);  // tok0 becomes i + 1
        }

        macquire(tok0, i);  // wait until tok0 >= i
        promotion(c[i]);
    }
    ...
}
```

Above pseudocode gives an example of how to use Zmasync to implement DeepGEMM in AME.
The `async_matmul` function is a non-blocking matrix multiplication function
implemented with asynchronous matrix store instructions,
which retires from the pipeline without waiting for the completion.
After asynchronous matrix store instructions in `async_matmul` function is finally completed,
`mrelease` will increment the sync register by one.
`macquire` blocks until the sync register value reaches or exceeds the given threshold (i.e., `tok >= threshold`), ensuring that the corresponding stores have completed before promotion begins. Note that an exact match is not required — if the sync register has advanced beyond the threshold, `macquire` still proceeds immediately. Without Zmasync, all operations would execute sequentially on the core, with no overlap between GEMM and promotion.
