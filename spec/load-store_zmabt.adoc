The legal matrix shapes of load/store instructions are:

* `mla` / `msa`: matrix A, stem:[mtilem \le TLEN / TRLEN], stem:[mtilek \le TRLEN / EW_A]
* `mlb` / `msb`: matrix B, stem:[mtilen \le TLEN / TRLEN], stem:[mtilek \le TRLEN / EW_B]
* `mlc` / `msc`: matrix C, stem:[mtilem \le TLEN / TRLEN], stem:[mtilen \le ROWNUM]

The effective memory element widths are determined by the programmed `mcfg` state. The accumulator always uses 32-bit slots, so a narrow nominal C format does not increase N.

The transposed variants `mlat` / `mlbt` / `mlct` and `msat` / `msbt` / `msct` use the same tile shapes as their non-transposed counterparts, but interpret memory layout in transpose mode.

The whole-register variants use the same matrix-class selection and the same register-class rules as the tile variants. They transfer the entire architectural register state selected by the instruction.

Taking TLEN=512, TRLEN=128, and ALEN=512 as an example:

* matrix A and B tile registers support up to 4 rows
* matrix C accumulation registers support up to 4 rows
* the maximum K depends on the tile-register input width, while the maximum N remains 4 for every supported nominal C format
