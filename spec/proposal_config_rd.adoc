== 提案：Config 指令增加 rd 写回（类似 vsetvl）

[WARNING]
====
**待讨论** — 本文档为配置指令编码改进提案，尚未定稿。
====

=== 问题

当前 `msettile{m|k|n}[i]` 指令的 bits[11:7] 固定为 `00000`，不写回任何 GPR。软件设置 tile 大小后，硬件会将请求值 clamp 到硬件支持的最大值，但软件无法直接获知 clamp 后的实际值，必须额外读取 `mtilem/mtilek/mtilen` CSR：

```
# 当前：需要两条指令才能获取实际 tile 大小
msettilemi 64       # 请求 mtilem=64，硬件可能 clamp 到 16
csrr t0, mtilem     # 额外读 CSR 才能知道实际值是 16
```

RISC-V V 扩展的 `vsetvli` 不存在这个问题——它直接将实际 VL 写回 rd：

```
vsetvli t0, a0, e8, m1   # t0 = 实际设置的 VL
```

=== 提案

将 bits[11:7] 改为 rd 字段，`msettile{m|k|n}[i]` 将实际（clamp 后的）tile 大小写回 rd。当 rd=x0 时行为与当前一致（丢弃返回值）。

=== 指令语义

[cols="^3,^6"]
|===
| *指令* | *语义*
| msettilemi rd, uimm10 | mtilem = min(uimm10, TMMAX); rd = mtilem
| msettileki rd, uimm10 | mtilek = min(uimm10, TKMAX); rd = mtilek
| msettileni rd, uimm10 | mtilen = min(uimm10, TNMAX); rd = mtilen
| msettilem rd, rs1     | mtilem = min(x[rs1], TMMAX); rd = mtilem
| msettilek rd, rs1     | mtilek = min(x[rs1], TKMAX); rd = mtilek
| msettilen rd, rs1     | mtilen = min(x[rs1], TNMAX); rd = mtilen
|===

当 rd = x0 时，写回被丢弃，行为与当前编码完全兼容。

=== 编码表

.Configuration Instructions (`func3=000`, `inst[27:26]=00`)
[cols="^2,^2,^2,^8"]
|===
| *func4* | *inst[25]* | *rd* | *Instruction*
| 0000    | 0          | 00000 | minit
| 0001    | 0          | rd    | msettileki rd, uimm10
| 0010    | 0          | rd    | msettilemi rd, uimm10
| 0011    | 0          | rd    | msettileni rd, uimm10
| 0001    | 1          | rd    | msettilek rd, rs1
| 0010    | 1          | rd    | msettilem rd, rs1
| 0011    | 1          | rd    | msettilen rd, rs1
|===

=== 使用示例

```
# 改进后：一条指令同时设置 tile 大小并获取实际值
msettilemi t0, 64       # mtilem = min(64, TMMAX); t0 = 实际值

# 尾部处理循环
loop:
    msettilem t0, a1    # t0 = min(remaining_m, TMMAX)
    # 直接用 t0 计算地址偏移，无需额外 CSR 读取
    ...
    sub a1, a1, t0
    bnez a1, loop
```

对比 V 扩展的典型用法：

```
# V 扩展
loop:
    vsetvli t0, a0, e8, m1   # t0 = actual VL
    vle8.v v0, (a1)
    sub a0, a0, t0
    ...

# 矩阵扩展（改进后）
loop:
    msettilem t0, a0         # t0 = actual tile_m
    mlae8 tr0, a1, a2
    sub a0, a0, t0
    ...
```

=== 对 minit 的影响

`minit`（func4=0000）当前 rd=00000。可以保持不变（minit 不返回有意义的值），或者让 minit 也支持 rd 写回某个状态值（如硬件能力信息）。建议保持 rd=00000 不变。

=== 优缺点

*优点：*

* 消除冗余 CSR 读取，tile 尾部处理循环减少一条指令
* 与 RISC-V V 扩展的 vsetvl 设计模式一致，降低程序员学习成本
* 完全向后兼容：rd=x0 时行为不变
* 无需额外编码空间，利用已有的 5 个 wasted bits

*缺点：*

* 微架构需要增加从 config 单元到 GPR 写回端口的数据通路
* 汇编语法变更，需要更新工具链（汇编器/反汇编器）
