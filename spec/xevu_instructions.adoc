[[xevu-instructions]]
=== Instructions

Operands are written `vd, vs1, vs2`. Let src2/src1 be the required old
source elements and acc the old destination. Ordinary subtraction and
division compute `vs2 op vs1`. Results apply only to active elements;
other registers are unchanged. `low` retains SEW bits, `signed` interprets
two's complement, and `clamp` limits to the signed SEW-bit range.

==== Configuration Instructions

`xv.setvli rd, rs1, vtype_uimm8` and `xv.setvl rd, rs1, rs2` normalize
configuration as in <<xevu-configuration>> and return actual VL in rd.
The register form reads full VTYPE from x[rs2]. The returned VL is
available to scalar dependencies without a CSR drain; completion does
not write rd a second time.

[[xevu-e0-memory]]
==== Load and Store Instructions

`xv.load vd, rs1, sew` and `xv.store vs, rs1, sew` transfer element
`idx` at `x[rs1] + idx*(SEW/8)` for `0 <= idx < VL`. The base must be
naturally aligned to SEW/8 bytes. Loads follow VTA; stores touch only
active bytes. There are no indexed-memory, strided, segmented, or masked
forms. D selects vector data for both directions; neither writes a GPR.

`load.e0`/`store.e0` transfer one 32-bit word at x[rs1] using vector
element zero when global VL is nonzero, otherwise nothing. They require
FP32/m1 and F3=010 and leave global VL unchanged. E0 loads follow the
local-length-one tail rule. E0 stores have the same partial-line and
completion constraints as ordinary stores; see <<xevu-memory-model>>
and <<xevu-fence>>.

==== Arithmetic Instructions

.Active-element arithmetic
[cols="3,7",options="header"]
|===
| Instruction (prefix `xv.`) | Result or operation
| add / sub / mul | low(src2 + src1) / low(src2 - src1) / low(src2 * src1)
| mac | low(src2 * src1 + acc)
| and / or / xor | Bitwise src2 op src1
| sll / srl / sra | Shift src2 by unsigned(src1) AND (SEW-1); left / logical right / signed arithmetic right; retain SEW bits
| min / max; minu / maxu | Signed minimum/maximum; unsigned minimum/maximum
| wadd / wsub / wmul | Sign-extend inputs, add/subtract/multiply, return 2*SEW bits
| satadd / satsub | clamp(signed(src2) + signed(src1)) / clamp(signed(src2) - signed(src1))
| fadd / fsub / fmul / fdiv | RNE(src2 op src1), same FP format
| fmacc | RNE(src2 * src1 + acc), fused with one final rounding
| fmin / fmax | Floating-point minimum/maximum, subject to the review below
| fsqrt | RNE(sqrt(src2)), same FP format
| frsqrt7 / frec7 | RVV seven-bit reciprocal-square-root / reciprocal estimate of src2
| fsgnjx | Magnitude bits of src2, with sign(src2) XOR sign(src1)
|===

Ordinary integer arithmetic is modular and sets no arithmetic flags;
signed saturation sets sticky EVXSAT when clamping occurs. Widening
produces VL results with destination width/group twice the source;
its only widths are 8-to-16 and 16-to-32.

[[xevu-floating-point]]
===== Floating-Point Rules

FP16/FP32 arithmetic uses fixed RNE and accrues EFFLAGS, independently
of CPU/matrix flags. Ordinary add/multiply/divide handle subnormals.
Min/max choose the numerical result for unequal finite inputs, the
numeric operand with one NaN, and canonical quiet NaN with two NaNs.
*Implementation review:* signed-zero ties, NaN flags, and inactive-element
exception handling still differ or need review in RTL/reference models;
this also applies to reductions and E0/scalar-source max.

[[xevu-rvv-math]]
===== Square Root, Estimates, and Sign XOR

`xv.fsqrt vd, vs2, sew` maps to RVV `vfsqrt.v`. It computes a
correctly rounded FP16/FP32 square root: signed zero is preserved,
+infinity is unchanged, and a negative nonzero input or signaling NaN
returns canonical quiet NaN with NV. A quiet NaN returns canonical quiet
NaN; inexact finite results accrue NX.

`xv.frsqrt7 vd, vs2, sew` and `xv.frec7 vd, vs2, sew` map to
`vfrsqrt7.v` and `vfrec7.v`. They use the RVV lookup-estimate and
special-value/exception rules, not a full-precision rounded `1/sqrt(x)`
or `1/x`. Positive finite estimates have approximately seven bits of
precision; refinement is a software choice. Signed-zero inputs yield
signed infinity with DZ; reciprocal-square-root of a negative nonzero
input yields canonical quiet NaN with NV. Reciprocal estimates accept
negative finite inputs; signaling NaNs accrue NV. Estimate overflow and
other flags follow the corresponding RVV operation.

`fsgnjx` maps to `vfsgnjx.vv`, copying all non-sign bits of src2 and
XORing the two source sign bits. It never raises FP exceptions, even
for signaling-NaN bit patterns. `xv.fabs vd, vs, sew` is an alias for
`xv.fsgnjx vd, vs, vs, sew`, not a new encoding.

[[xevu-exp2]]
===== EXP2

`xv.exp2` approximates `2^src2`, not the natural exponential, in FP16/FP32.
Special cases are: +/-0 gives +1; +infinity gives +infinity; -infinity
gives +0; quiet NaN gives canonical quiet NaN; signaling NaN additionally
sets NV; nonzero subnormal input gives +1 and NX. Other listed special
cases set no flags. Overflow returns
+infinity with OF/NX; tiny inexact results set UF/NX, and approximation
or rounding inexactness contributes NX. DZ is not generated.
*Numerical limitation:* no maximum ULP error or correctly rounded result
is promised; bit-exact checking requires a frozen implementation profile,
not a host `exp2` substitution.

[[xevu-e0]]
===== E0 and Scalar-Source Forms

The arithmetic E0 forms are `fadd.e0`, `fsub.e0`, `fmul.e0`, `fdiv.e0`,
`fmax.e0`, `exp2.e0`, `fsqrt.e0`, `frsqrt7.e0`, and `frec7.e0`.
They require FP32/m1 and F3=010, read source
element zero, and write only vd[0] when VL is nonzero; VL=0 does nothing.
EXP2, square root, and both estimates are unary. Other elements follow
VTA at local length one; nothing is
broadcast and global VL is unchanged.

`fadd.scalar`, `fsub.scalar`, `fmul.scalar`, and `fmax.scalar` also require
FP32/m1 and F3=010, but compute vs2[idx] op old(vs1[0]) for every active
element. The scalar is an EVU element, not a CPU GPR/FPR. Read it before
any destination update, including vd=vs1; these forms do not change VL.

[[xevu-width-conversions]]
==== Width and Integer/FP Conversion Instructions

Unary syntax is `xv.<operation> vd, vs2, sew`; immediate syntax is
`xv.<operation> vd, uimm5, vs2, sew`. Widths follow
<<xevu-encoding>>. All forms leave global VL/VTYPE unchanged.

.RVV-mapped conversions
[cols="3,3,5",options="header"]
|===
| Instruction (prefix `xv.`) | Saturn/RVV operation | Meaning
| fwcvt.f.f | vfwcvt.f.f.v | FP16 to FP32, with FP NaN/exception rules
| fncvt.f.f | vfncvt.f.f.w | FP32 to FP16 with RNE and FP exception flags
| fcvt.x.f | vfcvt.x.f.v | FP32 to signed INT32 with RNE and RVV invalid-conversion rules
| fcvt.f.x | vfcvt.f.x.v | Signed INT32 to FP32 with RNE; NX if inexact
| nclip.imm | vnclip.wi | Arithmetic right shift of a signed 2*SEW-bit source, RNU rounding, then signed SEW-bit saturation
| nsrl.imm | vnsrl.wi | Logical right shift of a 2*SEW-bit source, then keep its low SEW bits
| zext2 / sext2 | vzext.vf2 / vsext.vf2 | Zero-/sign-extend SEW/2-bit source to SEW bits
|===

For widening, source EMUL=LMUL and destination EMUL=2*LMUL. For narrowing,
destination EMUL=LMUL and source EMUL=2*LMUL. Extensions use destination
EMUL=LMUL and source EMUL=LMUL/2. Each produces VL destination elements;
EMUL must be within 1/8 through 8. Integer EMUL groups are aligned and
must end by ev31; fractional groups occupy the low part of one register.
Thus, for example, e16/m1 `fwcvt.f.f` reads one register and writes two,
whereas e16/m1 `fncvt.f.f` reads two and writes one. e16/m1 `zext2`
reads the low half of one register and writes one full register.

Disjoint groups are always permitted. Narrowing may overlap only at the
low part, with vd=vs2. Widening may overlap only with the source at the
high end of the destination and source EMUL at least one. The same
high-end rule applies to extension, whose source EMUL must then be at
least one (LMUL at least two). Illegal width, alignment, range, EMUL,
overlap, and nonzero unary S1 checks still apply at VL=0.

Both narrowing shifts mask uimm5 by (2*SEW-1). `nclip.imm` rounds using
fixed VXRM=0 (RNU: ties round upward), not nearest-even, and sets EVXSAT
only if the rounded signed value is clamped. Shift zero performs pure
saturation. `nsrl.imm` truncates without rounding or saturation. These
shifts and integer extensions do not accrue EFFLAGS; `nsrl.imm` and
extensions also leave EVXSAT unchanged. FP/integer conversions accrue
EFFLAGS, not EVXSAT.

[[xevu-low-precision]]
==== Low-Precision Conversion Instructions

These eighteen conversions use e32/m1, one architectural register per
operand, and VL logical values, with `0 <= VL <= EVLEN/32`. Each requires
F3=010 and leaves global VL/VTYPE unchanged. The mnemonic names the
destination format before the source format. No masked, E0, or scalar-result
form is defined. The format is selected by the opcode, not by register tags.

.Low-precision operations
[cols="3,1,1,4",options="header"]
|===
| Instruction (prefix `xv.`) | funct7 | EVCAP bit | Operation
| cvt.i8.f32 | 70 | 29 | FP32 to signed INT8
| cvt.e4m3.f32 | 71 | 29 | FP32 to E4M3FN
| cvt.e5m2.f32 | 72 | 29 | FP32 to E5M2
| cvt.f32.e4m3 | 73 | 29 | E4M3FN to FP32
| cvt.mxfp8.f32 | 74 | 29 | FP32 / UE8M0 scale to E4M3FN
| cvt.mxfp4.f32 | 75 | 29 | FP32 / UE8M0 scale to E2M1
| cvt.u8.f32 | 27 | 31 | FP32 to UINT8
| cvt.f32.i8 | 28 | 31 | Signed INT8 to FP32
| cvt.f32.u8 | 29 | 31 | UINT8 to FP32
| cvt.e2m1.f32 | 2a | 31 | FP32 to E2M1
| cvt.f32.e5m2 | 2b | 31 | E5M2 to FP32
| cvt.f32.e2m1 | 2c | 31 | E2M1 to FP32
| cvt.bf16.f32 | 2d | 33 | FP32 to BF16
| cvt.f32.bf16 | 2e | 33 | BF16 to FP32
| cvt.mxe5m2.f32 | 78 | 32 | FP32 / UE8M0 scale to E5M2
| cvt.f32.mxe4m3 | 79 | 32 | E4M3FN * UE8M0 scale to FP32
| cvt.f32.mxe5m2 | 7a | 32 | E5M2 * UE8M0 scale to FP32
| cvt.f32.mxfp4 | 7b | 32 | E2M1 * UE8M0 scale to FP32
|===

The twelve unscaled forms use `xv.<operation> vd, vs2` with S1=0.
The six scaled forms use `xv.<operation> vd, scale, vs2`, where scale
is an EVU register and its old element-zero low byte is held for the whole
command. Register ev0 is a valid scale source. The legacy `mxfp8` spelling
selects E4M3FN; it does not choose E4M3/E5M2 dynamically.

Destination must differ from the data source and, for scaled forms,
from the scale source; the two sources may be the same register.
Non-m1 groups, wrong encoded or effective widths, forbidden overlap,
nonzero unary S1, and unsupported capabilities are illegal even at VL=0.
There is no architectural VSTART or public masked conversion form.

===== Packed Register Layout

Every array begins at the low end of its register. In either conversion
direction, logical element idx occupies the following bits:

[cols="2,3,3",options="header"]
|===
| Format | Bit range | Bytes used for VL values
| FP32 | `[32*idx+31:32*idx]` | `4*VL`
| BF16 | `[16*idx+15:16*idx]` | `2*VL`
| INT8 / UINT8 / E4M3FN / E5M2 | `[8*idx+7:8*idx]` | `VL`
| E2M1 | `[4*idx+3:4*idx]` | `ceil(VL/2)`
|===

FP4 even-indexed elements occupy the low nibble of each byte. An odd
FP4 output VL clears the unused high nibble in the final written byte;
FP4 input ignores that nibble. Conversion writes exactly the destination
byte count in the table and preserves every subsequent byte regardless
of VTA. Source bits outside the active packed array are ignored.
Legal VL=0 leaves all registers and flags unchanged.

At EVLEN=4096, one command converts at most 128 logical values. Its
maximum output is 512 FP32 bytes, 256 BF16 bytes, 128 eight-bit bytes,
or 64 FP4 bytes. Packed results remain in the destination register.
Use ordinary e8 loads/stores with the required byte VL to transfer packed
data, then restore e32/m1 before conversion; e16 loads/stores can also
transfer BF16 bit patterns. Loading a halfword does not give it an
arithmetic type.

===== Rounding and Integer Conversion

Rounding is fixed RNE. Only active elements contribute flags to EFFLAGS;
none of these conversions sets EVXSAT, including integer saturation.
No conversion generates DZ. A valid inexact result sets NX.

INT8 and UINT8 encoding round the numerical FP32 value to an integer,
then clamp to [-128,127] or [0,255]. An invalid conversion sets NV and
does not set NX: NaN maps to the positive maximum; positive overflow
or infinity maps to the positive maximum; negative overflow or infinity
maps to -128 or zero respectively. A negative UINT8 input that rounds
to zero is valid (for example, -0.5 gives zero with NX under RNE);
a negative rounded nonzero integer gives zero with NV.
INT8 stores a two's-complement byte. Both integer-to-FP32 directions
are exact for every input and set no flags. These operations have no
zero-point or affine scaling parameter.

===== FP8 and FP4 Formats

E4M3 in the mnemonic denotes E4M3FN. The format and special-value rules
apply to raw encoding and to the corresponding scaled encoding:

* E4M3FN has one sign bit, four exponent bits with bias 7, and three
  fraction bits. It has signed zero, subnormals down to 2^-9, maximum
  finite magnitude 448, and NaN codes 0x7f/0xff, with no infinity or
  signaling NaN. FP32 NaNs encode as 0x7f; an FP32 signaling NaN sets NV.
  Overflow or infinity saturates to signed 448 with OF/NX.
* E5M2 has one sign bit, five exponent bits with bias 15, and two
  fraction bits. It has signed zero, subnormals down to 2^-16, maximum
  finite magnitude 57344, infinities, and signaling/quiet NaNs.
  The high fraction bit distinguishes quiet NaN. NaNs encode as 0x7e,
  with NV for signaling input NaN. RNE overflow produces signed infinity
  with OF/NX; an input infinity is exact.
* E2M1 has one sign bit, two exponent bits with bias 1, and one fraction
  bit. Finite magnitudes are {0, 0.5, 1, 1.5, 2, 3, 4, 6}, including
  signed zero; it has no NaN or infinity. Overflow/infinity saturates to
  signed 6 with OF/NX. An input NaN gives positive 6 (code 0x7) with NV.

For FP8/FP4 encoding, finite overflow is decided after rounding to the
format precision: a value that rounds to the maximum finite value sets
NX without OF. Tiny inexact encoding sets UF/NX when the final rounded
payload is subnormal or zero; rounding up to minimum normal sets NX
without UF. Exact subnormal results do not set UF.

Raw decoding is exact for every finite FP8/FP4 code, preserving signed
zero and subnormals. E4M3FN NaNs decode to canonical FP32 quiet NaN
0x7fc00000 without flags. E5M2 infinity is preserved; E5M2 NaNs decode
to the same canonical quiet NaN and signaling NaNs set NV. E2M1 has
no NaN input codes.

===== Given-Scale MXFP Conversion

The scale byte is UE8M0: codes k=0..254 mean `2^(k-127)`; code 127 is
unity and code 255 is NaN. Every active value uses this same scale.
It is not an E4M3 scale, and an E4M3 scale must not be passed directly
as the scale byte. Software or a separate operation produces the scale;
these conversions neither calculate an absolute maximum nor generate
a scale per block.

Encoding divides the exact FP32 input value by the scale before one
rounding to E4M3FN, E5M2, or E2M1, without an intermediate rounded FP32
division. Reconstruction multiplies the decoded payload by the scale.
Every finite product within the FP32 finite range is exact, including
subnormals: the smallest possible nonzero product is E5M2
`2^-16 * 2^-127 = 2^-143`, above FP32's minimum subnormal `2^-149`.
Finite reconstruction overflow returns signed infinity with OF/NX;
it never generates UF. Finite nonzero scales preserve payload infinity
and signed zero.

For a NaN scale, E4M3FN/E5M2 encoding returns their canonical NaN,
and reconstruction returns canonical FP32 quiet NaN. NV is set only
if the data operand is a signaling NaN. E2M1 encoding instead returns
positive 6 with NV, and E2M1 reconstruction returns canonical FP32 quiet
NaN with NV. NaN-scale results do not set OF, UF, or NX.

===== BF16 Conversion

BF16 has one sign bit, eight exponent bits with bias 127, and seven
fraction bits. FP16 remains the separate IEEE binary16 format with five
exponent and ten fraction bits. BF16 includes signed zero, infinities,
subnormals down to 2^-133, and signaling/quiet NaNs; the high fraction
bit distinguishes quiet NaN. Both directions canonicalize NaNs to
0x7fc0 (BF16) or 0x7fc00000 (FP32), with NV only for signaling input NaN.
Widening finite BF16 values to FP32 is exact, including subnormals;
signed zero and infinity are preserved.

FP32-to-BF16 conversion uses RNE. Finite overflow gives signed infinity
with OF/NX. Tininess is detected after rounding to BF16 precision with
an unbounded exponent, before rounding into the final bounded-exponent
subnormal representation; UF requires both tininess and inexactness.
Consequently, FP32 0x007f8000 rounds to BF16 0x0080 (minimum normal)
and still sets UF|NX (0x03). Testing only the stored result exponent
would give the wrong flag. Exact subnormal conversions set no flags.

[[xevu-block]]
==== Block Quantization Helpers

EVCAP[30] advertises `xv.block.amax` and `xv.block.pack`. Both require
F3=010 and e32/m1 and leave global VL/VTYPE unchanged. Their fixed VL
requirements apply even at VL=0. They change only the destination
windows specified below, preserving other bytes regardless of VTA;
neither writes a scalar register, accesses memory, nor sets EVXSAT.

===== Four Absolute Maxima

`xv.block.amax vd, q, vs2` (funct7=0x76) requires VL=64, immediate
q in 0..3 in S1, and vd different from vs2. S1 does not name a register.
For g=0..3, compute the maximum absolute FP32 value in
`vs2[16*g .. 16*g+15]` and write it to FP32 element `vd[4*q+g]`.
Thus exactly 16 bytes, starting at byte `16*q`, are written.
No seed operand is read.

NaNs are omitted from the maximum; an all-NaN group produces +0.
Absolute value maps -0 to +0 and either infinity to +infinity.
Any signaling NaN among the 64 inputs sets NV; quiet NaNs set no flags.
No OF, UF, DZ, or NX is generated.

===== FP32 Multiply and E2M1 Pack

`xv.block.pack vd, rs1, vs2` (funct7=0x77) requires VL=16. S1 names
the scalar GPR containing the 64-bit control word C. Its fields select
a source data group, a descriptor in the VRF, and a destination slot:

.Block-pack control word C
[cols="2,6",options="header"]
|===
| Bits | Meaning
| 4:0 | Descriptor vector register dreg, 0..31
| 6:5 | Source group g, 0..3; input FP32 elements `vs2[16*g .. 16*g+15]`
| 10:7 | Descriptor FP32-word index i, 0..15, in dreg
| 13:11 | Destination eight-byte slot s, 0..7
| 63:14 | Must be zero; nonzero values are illegal
|===

Read the old descriptor word `D = dreg[i]`. Bit D[31] is keep;
D[30:0] with a cleared sign bit forms the nonnegative FP32 multiplier a.
Software normally prepares a as an inverse scale. All FP32 encodings
with a cleared sign bit are accepted, including zero, subnormal,
infinity, and NaN; the instruction does not check reciprocal provenance.
The descriptor index and output slot are independent fields.

For j=0..15, calculate:

[source,text]
----
p[j] = RNE_FP32(old(vs2[16*g+j]) * a)
z[j] = keep ? p[j] : +0
payload[j] = RNE_E2M1(z[j])
----

The first operation is an ordinary FP32 multiplication with FP32
rounding and tininess after rounding. E2M1 conversion then follows
<<xevu-low-precision>>, including finite saturation and NaN handling.
This sequence has two rounding steps. Each pair of consecutive E2M1
values occupies one byte, earlier element in the low nibble. Write
exactly bytes `vd[8*s .. 8*s+7]`; all other bytes are preserved.

EFFLAGS ORs exceptions from all 16 FP32 multiplications and all 16
E2M1 conversions. Clearing keep replaces the products with +0 before
conversion and writes eight zero bytes, but still accrues multiplication
exceptions. For example, zero multiplied by +infinity with keep=0
writes zero payload and sets NV. The command generates no scale and
stores no scale metadata.

Data and descriptor values are read before this command's destination
update. All source/destination aliases are allowed, including vd=vs2,
vd=dreg, and vs2=dreg. Global VL=16 selects the fixed command size;
C selects which group of 16 source words is read, including groups
beyond the first 16 words of vs2.

==== Reduction and Permutation Instructions

[[xevu-reductions]]
===== Reductions

With VL nonzero, reductions combine the seed vs1[0] with vs2[0..VL-1]
and write only vd[0], in the same element format. Integer operators are
sum modulo 2^SEW, signed min/max, and bitwise and/or/xor. FP operators
are sum/min/max; min/max use <<xevu-floating-point>>. FP sum is unordered,
not an exact sum rounded once; reproducible checking must specify the
tree and intermediate precision. VL=0 leaves the destination unchanged,
including not copying the seed. Other destination elements follow VTA
with local output length one. There is no implicit CPU result or store.

===== Gather and Broadcast

`gather` takes unsigned same-SEW indices from vs1; `gather.imm` uses an
unsigned uimm5 (0-31). Each active output reads vs2[index] if index is
below VLMAX, otherwise zero. The bound is VLMAX, not VL: software must
initialize any selected source tail. Immediate zero broadcasts vs2[0].
Gather accesses registers, not memory, and uses disjoint destination/source
groups for portable behavior.

[[xevu-slide-review]]
===== Slide

`xv.slideup vd, rs1, vs2, sew` and `xv.slidedown vd, rs1, vs2, sew`
take the full unsigned 64-bit offset from scalar GPR x[rs1], captured
when the command is issued. x0 supplies offset zero. The offset is not
masked to SEW bits and is not read from an EVU register. These forms map
to Saturn's RVV `vslideup.vx` and `vslidedown.vx` respectively.

For active idx, slideup reads vs2[idx-offset] when idx >= offset and
preserves the old destination below offset. Slidedown reads vs2[idx+offset]
when the mathematical sum is below VLMAX, otherwise zero; a large offset
cannot wrap around. The bound is VLMAX, not VL, so initialize any selected
source tail. Both operations support SEW=8/16/32, leave VL/VTYPE and
arithmetic flags unchanged, and follow VTA beyond VL.

Source and destination groups must be aligned and in range. Slideup
requires disjoint groups even at offset zero; slidedown permits identical
groups. The scalar offset register is not subject to LMUL alignment.
These legality checks apply at VL=0; a legal VL=0 command changes nothing.

==== Completion and Synchronization Instructions

[[xevu-fence]]
===== XV.FENCE

`xv.fence` drains older computation, loads, stores, and final physical
memory responses before later scalar consumption. Queue acceptance is
not store completion. It returns no data and changes neither configuration
nor matrix sync registers. Check asynchronous errors after the drain;
a fence does not repair failures or acknowledge them. It covers the EVU
domain, not cross-hart publication or matrix-engine completion.
Dependencies between EVU instructions remain
hardware-managed and do not require a fence after each operation.

[[xevu-memory-sync]]
===== Shared-Memory Handoff

All boundaries require compiler memory ordering as well as the following
same-hart synchronization; cross-hart publication uses platform protocols.

[cols="3,7",options="header"]
|===
| Producer to consumer | Required boundary
| CPU to EVU | Publish input before the EVU load; current dispatch drains older scalar stores.
| EVU to CPU | XV.FENCE or another specified EVU drain before consumption.
| Matrix to EVU | With Zmasync, corresponding mrelease and successful macquire before the EVU load.
| EVU to matrix | XV.FENCE, then Zmasync mfence, before the matrix load.
|===

Synchronous matrix execution uses its defined store-completion boundary.
Matrix results require an explicit store and EVU load; synchronization
alone never transfers an accumulator into the EVU register file.

[[xevu-example]]
==== Usage Example

This softmax-like sequence uses VTYPE=0x10 (e32/m1) and already-published
input/constants. Process actual returned VL, looping for any remainder;
production code must also handle empty input and NaNs/infinities.

[source,text,options="unbreakable"]
----
xv.setvli      t0, count, 0x10
xv.load        ev1, input, e32
xv.load.e0     ev2, minus_infinity
xv.freduce.max ev3, ev2, ev1, e32
xv.fsub.scalar ev4, ev3, ev1
xv.load.e0     ev5, log2_e
xv.fmul.scalar ev4, ev5, ev4
xv.exp2        ev6, ev4, e32
xv.load.e0     ev7, zero
xv.freduce.sum ev8, ev7, ev6, e32
xv.gather.imm  ev9, 0, ev8, e32
xv.fdiv        ev10, ev9, ev6, e32
xv.store       ev10, output, e32
xv.fence
----
