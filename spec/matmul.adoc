Matrix multiplication operations take two matrix tiles, matrixA and matrixB, from matrix **tile registers** specified by `ms1` and `ms2`, and accumulate the multiplication result to matrixC specified by `md`, the output will overwrite the `md` **accumulation register**.

If the accumulation register is larger than the output matrix tile(matrixC) in bits, only the lower columns are updated and the higher parts are set by zeros.

This specification exposes a single architectural matrix multiply instruction, `mmacc`. The operand and accumulator types are determined by the programmed `mtype(ms1)`, `mtype(ms2)`, and `mtype(md)` state together with the matrix capability description reported by the implementation.

[cols="^2,^3,^3,^3"]
|===
| category   | instructions             | Operand Type            | Accumulator Type
| implementation-defined | mmacc | determined by `mtype(ms1)` / `mtype(ms2)` | determined by `mtype(md)`
|===

If `msaten` equals 1, the output should be saturated for combinations that define saturation behavior. Otherwise, the `mmacc` operation ignores overflow and wraps around the result when wraparound semantics are defined. If the programmed `mtype` state does not match a supported matrix multiply combination, executing `mmacc` raises an illegal instruction exception.

```
# matrix multiplication and accumulate, md = md + ms1 * ms2.
mmacc   md, ms2, ms1
```

Hardware executing unsupported instructions will raise illegal instruction exception.

For executing matrix multiplication instructions, illegal instruction exception will occur under unsupported mtilem/mtilen/mtilek setting. The illegal condition is when mtilem/mtilek/mtilen is bigger than TMMAX/TKMAX/TNMAX.
