Matrix multiplication operations take two matrix tiles, matrixA and matrixB, from matrix **tile registers** specified by `ms1` and `ms2`, and accumulate the multiplication result to matrixC specified by `md`, the output will overwrite the `md` **accumulation register**.

If the accumulation register is larger than the output matrix tile(matrixC) in bits, only the lower columns are updated and the higher parts are set by zeros.

This simplified specification exposes a single architectural matrix multiply instruction, `mmacc`. In the current simplified profile, `mmacc` is defined only for the type combination `mtype(ms1)=i8`, `mtype(ms2)=i8`, and `mtype(md)=i32`.

[cols="^2,^3,^3,^3"]
|===
| category   | instructions             | Operand Type            | Accumulator Type
|     Int    |   mmacc                  |    int8                 |  int32
|===

If `msaten` equals 1, the output should be saturated. Otherwise, the `mmacc` operation ignores overflow and wraps around the result. If the programmed `mtype` state does not match the defined `i8`/`i8`/`i32` combination, executing `mmacc` raises an illegal instruction exception.

```
# integer matrix multiplication and add, md = md + ms1 * ms2.
mmacc   md, ms2, ms1
```

Hardware executing unsupported instructions will raise illegal instruction exception.

For executing matrix multiplication instructions, illegal instruction exception will occur under unsupported mtilem/mtilen/mtilek setting. The illegal condition is when mtilem/mtilek/mtilen is bigger than TMMAX/TKMAX/TNMAX.
