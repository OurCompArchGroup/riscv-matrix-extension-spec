Matrix multiplication operations take two matrix tiles, matrixA and matrixB, from matrix **tile registers** specified by `ms1` and `ms2`, and accumulate the multiplication result into matrixC specified by `md`, which shall name an **accumulation register**.

`mmacc` updates only the active output tile region of `md` selected by the current `mtilem` and `mtilen` settings. The instruction is accumulative: for each active output element, the new value is computed as the previous accumulator value plus the matrix product contribution. The contents of `md` outside the active output tile region are unspecified after execution.

This specification exposes a single architectural matrix multiply instruction, `mmacc`. The operand and accumulator types are determined by the programmed `mcfg(ms1)`, `mcfg(ms2)`, and `mcfg(md)` state together with the matrix capability description reported by the implementation.

[cols="^2,^3,^3,^3"]
|===
| category   | instructions             | Operand Type            | Accumulator Type
| implementation-defined | mmacc | determined by `mcfg(ms1)` / `mcfg(ms2)` | determined by `mcfg(md)`
|===

If `msaten` equals 1, the output should be saturated for combinations that define saturation behavior. Otherwise, the `mmacc` operation ignores overflow and wraps around the result when wraparound semantics are defined. If the programmed `mcfg` state does not match a supported matrix multiply combination, executing `mmacc` raises an illegal instruction exception.

```
# matrix multiply-accumulate on the active output tile region.
# For active elements: md = md + ms1 * ms2.
mmacc   md, ms2, ms1
```

Hardware executing unsupported instructions will raise illegal instruction exception.

Executing a matrix multiplication instruction with unsupported `mtilem`, `mtilek`, or `mtilen` settings raises an illegal instruction exception. The programmed tile sizes are illegal when they exceed the architectural limits implied by `ROWNUM`, `TRLEN`, `ARLEN`, and the active operand and accumulator configuration selected by `mcfg`.
