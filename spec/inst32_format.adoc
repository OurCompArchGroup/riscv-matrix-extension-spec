The 32-bit Zames instruction formats fit under the custom-1 (`0101011`) major opcode. The `func3` field is the only top-level instruction-category selector in the Zames main body, and it is always located at bits `inst[14:12]`. Bits `inst[27:26]` are reserved and shall be written as `00` in all Zames main-body encodings. Any bit without an explicitly defined semantic role in the formats below is reserved and shall be written as zero.

The assigned `func3` values in the Zames main body are as follows:

[cols="^2,^8"]
|===
| *func3* | *Instruction Category*
| 000 | Configuration instructions
| 001 | Load/Store instructions
| 010 | Matrix multiplication instructions
| 011 | MISC instructions
| 100 | Optional extension encoding space
| 101 | Reserved
| 110 | Reserved
| 111 | Reserved
|===

The `md` / `ms1` / `ms2` fields use the same 3-bit register-index encoding:

[cols="^1,1"]
|===
| *Index* | *Matrix Register*
| 000 | tr0
| 001 | tr1
| 010 | tr2
| 011 | tr3
| 100 | acc0
| 101 | acc1
| 110 | acc2
| 111 | acc3
|===

The `mtype` configuration family reuses this same 3-bit encoding to select `mtype0` through `mtype7`, because `mtype` and matrix registers never occupy the same field in the same instruction format.

[cols="^1,1"]
|===
| *mtype_sel[2:0]* | *Target Type Register*
| 000 | mtype0 (type state for tr0)
| 001 | mtype1 (type state for tr1)
| 010 | mtype2 (type state for tr2)
| 011 | mtype3 (type state for tr3)
| 100 | mtype4 (type state for acc0)
| 101 | mtype5 (type state for acc1)
| 110 | mtype6 (type state for acc2)
| 111 | mtype7 (type state for acc3)
|===

==== Configuration Instructions

The configuration instruction category uses `func3 = 000`.

===== Configuration-IMM Format

This format is used by `minit` and the immediate tile-configuration instructions.

[wavedrom, ,svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: '0101011', type: 8},
  {bits: 5,  name: '0', attr: '00000', type: 8},
  {bits: 3,  name: 'func3', attr: '000', type: 8},
  {bits: 10, name: 'uimm10[9:0]', type: 4},
  {bits: 1,  name: 'mode', attr: '0', type: 8},
  {bits: 2,  name: 'rd', attr: '00', type: 8},
  {bits: 4,  name: 'func4', type: 5}
], config: {lanes: 1, hspace: 1000}}
....

===== Configuration-GPR Format

This format is used by the register tile-configuration instructions.

[wavedrom, ,svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: '0101011', type: 8},
  {bits: 5,  name: '0', attr: '00000', type: 8},
  {bits: 3,  name: 'func3', attr: '000', type: 8},
  {bits: 5,  name: 'rs1', type: 3},
  {bits: 5,  name: '0', attr: '00000', type: 8},
  {bits: 1,  name: 'mode', attr: '1', type: 8},
  {bits: 2,  name: '0', attr: '00', type: 8},
  {bits: 4,  name: 'func4', type: 5}
], config: {lanes: 1, hspace: 1000}}
....

===== Configuration-MTYPE Format

This format is used by `msettype`. The `Configuration-MTYPE` branch is separated from tile configuration so that matrix-type programming has its own dedicated encoding description.

`mcfg_d1` selects the target `mtype` register. The selector reuses the same 3-bit numbering as `tr0`-`acc3`, and the upper two bits of the 5-bit field are reserved zero.

[wavedrom, ,svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: '0101011', type: 8},
  {bits: 5,  name: 'mcfg_d1', type: 3},
  {bits: 3,  name: 'func3', attr: '000', type: 8},
  {bits: 13,  name: '0', type: 8},
  {bits: 4,  name: 'func4', attr: '0100', type: 5}
], config: {lanes: 1, hspace: 1000}}
....

- `inst[11:7]` is `mcfg_d1`
- `inst[24:20]` is `rs1`
- the low four bits of `x[rs1]` provide the new type code
- `inst[28:15]` is reserved zero

.Configuration Instructions (`func3=000`)
[cols="^2,^2,^8"]
|===
| *func4* | *mode (inst[25])* | *Instruction*
| 0000 | 0 | minit
| 0001 | 0 | msettileki
| 0010 | 0 | msettilemi
| 0011 | 0 | msettileni
| 0001 | 1 | msettilek
| 0010 | 1 | msettilem
| 0011 | 1 | msettilen
| 0100 | 0 | msettype
|===

==== Load/Store Instructions

The load/store instruction category uses `func3 = 001`. Types are not encoded in the instruction. They are determined by the programmed `mtype` state of the accessed matrix register.

The `func4` field is partitioned as follows:

- `func4[3]`: `whole`
- `func4[2]`: `transpose`
- `func4[1:0]`: matrix kind

Matrix-kind encoding:

[cols="^2,^8"]
|===
| *func4[1:0]* | *Matrix Kind*
| 00 | A matrix
| 01 | B matrix
| 10 | C matrix
| 11 | Reserved
|===

The `whole` bit is only defined for load/store instructions. Whole-register access with `transpose=1` is reserved.

===== Load/Store-Normal Format

[wavedrom, ,svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: '0101011', type: 8},
  {bits: 3,  name: 'md/ms3', type: 2},
  {bits: 2,  name: '0', attr: '00', type: 8},
  {bits: 3,  name: 'func3', attr: '001', type: 8},
  {bits: 5,  name: 'rs1', type: 3},
  {bits: 5,  name: 'rs2', type: 4},
  {bits: 1,  name: 'l/s', type: 6},
  {bits: 2,  name: '0', attr: '00', type: 8},
  {bits: 4,  name: 'func4', type: 5}
], config: {lanes: 1, hspace: 1000}}
....

===== Load/Store-Transpose Format

This format uses the same field layout as the normal load/store format, with `func4[2]=1` and `func4[3]=0`.

===== Load/Store-Whole Format

This format uses the same field layout as the normal load/store format, with `func4[3]=1` and `func4[2]=0`.

.Load/Store Instructions (`func3=001`)
[cols="^1,^1,^1,^2,^8"]
|===
| *whole* | *transpose* | *l/s* | *kind* | *Instruction*
| 0 | 0 | 0 | 00 | mla
| 0 | 0 | 0 | 01 | mlb
| 0 | 0 | 0 | 10 | mlc
| 0 | 0 | 1 | 00 | msa
| 0 | 0 | 1 | 01 | msb
| 0 | 0 | 1 | 10 | msc
| 0 | 1 | 0 | 00 | mlat
| 0 | 1 | 0 | 01 | mlbt
| 0 | 1 | 0 | 10 | mlct
| 0 | 1 | 1 | 00 | msat
| 0 | 1 | 1 | 01 | msbt
| 0 | 1 | 1 | 10 | msct
| 1 | 0 | 0 | 00 | mla.whole
| 1 | 0 | 0 | 01 | mlb.whole
| 1 | 0 | 0 | 10 | mlc.whole
| 1 | 0 | 1 | 00 | msa.whole
| 1 | 0 | 1 | 01 | msb.whole
| 1 | 0 | 1 | 10 | msc.whole
| 1 | 1 | 0/1 | 00-10 | Reserved
|===

==== Matrix Multiplication Instructions

The matrix multiplication category uses `func3 = 010`. Matrix multiplication type combinations are determined by `mtype(ms1)`, `mtype(ms2)`, and `mtype(md)`. Bits `inst[25:23]`, `inst[19:18]`, and `inst[11:10]` are reserved.

[wavedrom, ,svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: '0101011', type: 8},
  {bits: 3,  name: 'md', type: 2},
  {bits: 2,  name: '0', attr: '00', type: 8},
  {bits: 3,  name: 'func3', attr: '010', type: 8},
  {bits: 3,  name: 'ms1', type: 3},
  {bits: 2,  name: '0', attr: '00', type: 8},
  {bits: 3,  name: 'ms2', type: 4},
  {bits: 3,  name: '0', attr: '000', type: 8},
  {bits: 2,  name: '0', attr: '00', type: 8},
  {bits: 4,  name: 'func4', type: 5}
], config: {lanes: 1, hspace: 1000}}
....

.Matrix Multiplication Instructions (`func3=010`)
[cols="^2,^8"]
|===
| *func4* | *Instruction*
| 0000 | mmacc
| 0001-1111 | Reserved
|===

==== MISC Instructions

The misc category uses `func3 = 011`. Bits `inst[25:23]`, `inst[22:20]`, `inst[19:18]`, `inst[17:15]`, and `inst[11:10]` are reserved.
