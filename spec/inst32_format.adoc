The 32-bit instruction format fit under the custom-1(0101011) major opcode. There are three main types of instruction formats, as illustrated below.

All matrix instructions use func3 = 000. The Zmasync extension uses func3 = 001 to maintain a separate encoding space. The uop field distinguishes different instruction categories. Within each category, additional fields further differentiate specific instructions as shown in the tables below.

For the matrix instructions only with matrix register, md/ms1/ms2 fields indicate the matrix register indexes for the dest(src3)/src1/src2 matrix operands, d_size field indicates the destination operand size, s_size field indicates the source operand size, imm3/ctrl field indicates the immediate index of matrix row/column or more operation information, and uop field indicates the different micro-operation types.

The md/ms1/ms2 fields are 3-bit width to index the four tile registers and four accumulation registers.

[cols="^1,1"]
|===
| *md/ms1/ms2[2:0]*  | *Matrix Register Index*
|  000               |   tr0
|  001               |   tr1
|  010               |   tr2
|  011               |   tr3
|  100               |   acc0
|  101               |   acc1
|  110               |   acc2
|  111               |   acc3
|=== 

For matrix multiplication instructions, ms1/ms2 should be 000-011 for tile registers, and md should be 100-111 for accumulation registers. For matrix misc instructions, md/ms1/ms2 can be 000-111, according to the specific misc instruction.

The element sizes of d_size and s_size are as follows:

[cols="^1,1"]
|===
| *d/s_size[1:0]* | *Element Size*
|  00       | 8-bit
|  01       | 16-bit
|  10       | 32-bit
|  11       | 64-bit
|=== 


For the matrix instructions with GPR operand, rd/rs1/rs2 fields indicate the scaler register indexes for the dest/src1/src2 scaler operands.

For the matrix instructions with IMM10, imm10 fields indicates the 10-bit width immediate, usually used in configuration instruction.

The uop field (inst[27:26]) is the primary classifier that determines the instruction category. All instructions are first categorized by their uop value, then further differentiated within each category using additional encoding fields.

.Instruction Category Encoding (uop field)
[cols="^2,^8"]
|===
| *uop* | *Instruction Category*
| 00    | Configuration instructions
| 01    | Load/Store instructions
| 10    | Matrix Multiplication instructions
| 11    | MISC instructions
|===

==== Configuration Instructions

The func4 field distinguishes m/n/k configuration, and inst[25] indicates whether the configuration parameter is from imm10 field (inst[25]=0) or rs1 register (inst[25]=1). When inst[25]=0, the tile size is encoded as a 10-bit unsigned immediate (uimm10) in the instruction, which is suitable for compile-time known constant tile sizes; when inst[25]=1, the tile size is read from the general-purpose register rs1, which is used when the tile size is computed at runtime, such as handling the tail iterations of a tiling loop.

==== Load/Store Instructions

The func4 field defines load/store types (A/B/C matrix type, transpose type). Inst[25] is the ls field indicating load/store direction: 0=Load, 1=Store. The d_size field indicates the element size (8/16/32/64 bits).

[wavedrom, ,svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: '0101011', type: 8},
  {bits: 3,  name: 'md/ms3', type: 2},
  {bits: 2,  name: 'd_size', type: 7},
  {bits: 3,  name: 'func3', attr: '000', type: 8},
  {bits: 5,  name: 'rs1', type: 3},
  {bits: 5,  name: 'rs2', type: 4},
  {bits: 1,  name: 'l/s', type: 6},
  {bits: 2,  name: 'uop', attr: '01', type: 8},
  {bits: 4,  name: 'func4', type: 5},
], config: {lanes: 1, hspace: 1000}}
....

.Load/Store Instructions (uop=01)
[cols="^2,^2,^8"]
|===
| *func4* | *inst[25] (ls)* | *Instruction*
| 0000    | 0               | mlae8 (load A matrix)
| 0001    | 0               | mlbe8 (load B matrix)
| 0010    | 0               | mlce{8,32} (load C matrix)
| 0010    | 1               | msce{8,32} (store C matrix)
| 0100    | 0               | mlate8 (load A matrix transpose)
| 0101    | 0               | mlbte8 (load B matrix transpose)
| 0110    | 0               | mlcte{8,32} (load C matrix transpose)
| 0110    | 1               | mscte{8,32} (store C matrix transpose)
|===

==== Matrix Multiplication Instructions

The A/B/C matrices come from ms1/ms2/ms3 fields. The d_size field indicates the element size of C matrix (d_size=10 for 32-bit). The s_size indicates the element size of A/B matrix (s_size=00 for 8-bit). The func4 is 0001 for integer matrix multiplication. For the current simplified specification, only signed `int8 x int8 -> int32` matrix multiplication is supported, where ctrl (inst[25:23]) = 011.

[wavedrom, ,svg]
....
{reg: [
  {bits: 7,  name: 'opcode', attr: '0101011', type: 8},
  {bits: 3,  name: 'md/ms3', type: 2},
  {bits: 2,  name: 'd_size', type: 7},
  {bits: 3,  name: 'func3', attr: '000', type: 8},
  {bits: 3,  name: 'ms1', type: 3},
  {bits: 2,  name: 's_size', type: 7},
  {bits: 3,  name: 'ms2', type: 4},
  {bits: 3,  name: 'imm3/ctrl', type: 6},
  {bits: 2,  name: 'uop', attr: '10', type: 8},
  {bits: 4,  name: 'func4', type: 5},
], config: {lanes: 1, hspace: 1000}}
....

.Matrix Multiplication Instructions (uop=10)
[cols="^2,^8"]
|===

| 011                  | mmacc.w.b (`int8 x int8 -> int32`)
|===

==== MISC Instructions

The func4 field is 0000 for mzero instruction. When ms1 or ms2 are not used, these fields are set to zero. For the mzero instruction, the imm3 field (inst[25:23]) is fixed to 000.
