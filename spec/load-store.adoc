Matrix load instructions load matrix data from memory into matrix registers, and matrix store instructions store matrix data from matrix registers back to memory.

The data type of a load or store instruction is not encoded by dedicated width fields. Instead, the type is determined entirely by the programmed `mcfg` state of the destination register for loads and the source register for stores.

The base address is held in `rs1`, and the row stride in bytes is held in `rs2`. `md` / `ms3` identifies the destination matrix register for a load and the source matrix register for a store.

Load/store instructions are organized by:

- matrix class: A / B / C
- direction: load / store
- access mode: normal / transpose / whole

The active tile shape is based on stem:[C = A \times B^T]:

- A matrix tile shape: stem:[mtilem \times mtilek]
- B matrix tile shape: stem:[mtilen \times mtilek]
- C matrix tile shape: stem:[mtilem \times mtilen]

==== Normal Load/Store Instructions

```
# md destination, rs1 base address, rs2 row byte stride
mla  md, (rs1), rs2      # load A tile
mlb  md, (rs1), rs2      # load B tile
mlc  md, (rs1), rs2      # load C tile

# ms3 source, rs1 base address, rs2 row byte stride
msa  ms3, (rs1), rs2     # store A tile
msb  ms3, (rs1), rs2     # store B tile
msc  ms3, (rs1), rs2     # store C tile
```

==== Transposed Load/Store Instructions

```
# md destination, rs1 base address, rs2 row byte stride
mlat md, (rs1), rs2      # load A tile, transpose mode
mlbt md, (rs1), rs2      # load B tile, transpose mode
mlct md, (rs1), rs2      # load C tile, transpose mode

# ms3 source, rs1 base address, rs2 row byte stride
msat ms3, (rs1), rs2     # store A tile, transpose mode
msbt ms3, (rs1), rs2     # store B tile, transpose mode
msct ms3, (rs1), rs2     # store C tile, transpose mode
```

==== Whole Register Load/Store Instructions

The whole-register variants are not a separate top-level instruction family. They are the same A/B/C load/store instructions with the `whole` mode bit set to 1. The assembly notation in this specification uses a `.whole` suffix to make the mode visible.

```
mla.whole md, (rs1), rs2   # load whole A register
mlb.whole md, (rs1), rs2   # load whole B register
mlc.whole md, (rs1), rs2   # load whole C register

msa.whole ms3, (rs1), rs2  # store whole A register
msb.whole ms3, (rs1), rs2  # store whole B register
msc.whole ms3, (rs1), rs2  # store whole C register
```

Whole-register access with transpose mode is reserved.

Whole-register accesses transfer the complete architectural contents of the selected matrix register and do not depend on the programmed `mtilem` / `mtilek` / `mtilen` values.

Executing a non-`.whole` matrix load or store instruction will result in an illegal instruction exception under unsupported `mtilem` / `mtilek` / `mtilen` settings.

Matrix load/store instructions validate the programmed `mcfg` state of the accessed matrix register. A mismatch between the instruction's defined matrix class semantics and the programmed `mcfg` state raises an illegal instruction exception.

For A/B matrix accesses, the destination register of a load and the source register of a store shall be a tile register (`tr0`-`tr3`). For C matrix accesses, the destination register of a load and the source register of a store shall be an accumulation register (`acc0`-`acc3`).

NOTE: Whole matrix load and store instructions are primarily used for context save and restore.
